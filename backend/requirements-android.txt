# Backend embutido no APK Android, sabor `local` (Chaquopy 17.2, Python 3.13). Não instalar
# na VPS nem no desktop: esses usam o requirements.txt.
#   Instalado pelo frontend/android/app/build.gradle:
#   pip { options("--find-links", "wheels"); install("-r", "../../../backend/requirements-android.txt") }
#
# Lock: tudo com ==, transitivas incluídas (resolvido com o pip no Python 3.13; mesmas
# versões do .venv do backend onde o Android permite). O pip do Chaquopy só aceita wheel:
# - pydantic-core: wheel Android própria em frontend/android/app/wheels/ (+ SHA256SUMS),
#   saída do .github/workflows/wheels-android.yml (o pydantic 2.14.2 fixa a 2.50.2);
# - cryptography, cffi, argon2-cffi-bindings e chaquopy-libffi (dependência da wheel de
#   cffi): wheels do índice do Chaquopy, as únicas cp313 de lá (o cryptography liga no
#   OpenSSL do runtime, libcrypto_python.so);
# - o resto: wheels puras do PyPI (o wrapt usa a py3-none-any).
# Fora de propósito: webauthn (pede cryptography>=49; a passkey é rota só da VPS),
# pywebpush (push é rota só da VPS) e o [standard] do uvicorn (fica asyncio + h11).
#
# pip-audit (decisão O4 do programa android-local): o cryptography 42.0.8 tem 7 avisos
# (11 linhas com os repetidos), nenhum aplicável. No Android o backend usa do cryptography
# só a Fernet (app/cripto.py, app/desktop.py): nada de X.509, TLS ou chave pública EC por
# ele (o TLS do httpx é o módulo ssl do Python).
# - PYSEC-2026-1284 (CVE-2024-12797, GHSA-79v4-65xg-pq4g), GHSA-h4gh-qq45-vh27 e
#   GHSA-537c-gmf6-5ccf: OpenSSL estático das wheels do PyPI. A wheel do Chaquopy não traz
#   essa cópia (usa o OpenSSL do runtime), e o backend não faz TLS pelo cryptography.
# - PYSEC-2026-2141 (CVE-2026-26007, GHSA-r6ph-v2qm-q3c2): subgrupo não validado ao
#   carregar chave pública EC de curva SECT. Sem chave EC no Android (passkey fica na VPS).
# - PYSEC-2026-35 (CVE-2026-34073, GHSA-m959-cc7f-wv43), PYSEC-2026-3553 (CVE-2026-69249,
#   GHSA-jwv3-5hgf-82ww) e PYSEC-2026-3554 (CVE-2026-69248, GHSA-m2h6-j472-rp4c):
#   validação de cadeia X.509 (cryptography.x509.verification), que o backend não usa.
# Rever a cada cryptography novo no índice do Chaquopy e antes de usar no Android outra
# primitiva além da Fernet (a S6 prevê ChaCha20-Poly1305, Ed25519 e X25519):
#   pip-audit -r backend/requirements-android.txt --no-deps --disable-pip \
#     --ignore-vuln PYSEC-2026-1284 --ignore-vuln GHSA-h4gh-qq45-vh27 \
#     --ignore-vuln GHSA-537c-gmf6-5ccf --ignore-vuln PYSEC-2026-2141 \
#     --ignore-vuln PYSEC-2026-35 --ignore-vuln PYSEC-2026-3553 --ignore-vuln PYSEC-2026-3554
